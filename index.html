Befehlskatalog des Servers

 

 
Der eingebaute Katalog stammt aus Windows PowerShell 5.1 auf Windows Server 2025. Die tatsächlich verfügbaren Befehle hängen von Windows-Version und vorhandenen Rollenmodulen ab. Microsoft 365 ist nicht enthalten.

 
  1. Das Exportskript herunterladen und auf dem gewünschten Windows-Rechner mit Windows PowerShell 5.1 ausführen.
  2. Die erzeugte PowerHelp-Catalog.json hier importieren. Der Import ergänzt oder aktualisiert den eingebauten Katalog.

 
Das Skript fragt Befehlsmetadaten ab und führt die gefundenen Administratorbefehle nicht aus. Es installiert nichts und lädt keine Hilfe aus dem Internet. -AllAvailable bezieht auch bereits vorhandene weitere Module ein.

 

 
Imports werden mit dem Projekt gespeichert. Dynamische Parameter können vom gewählten Pfad oder Provider abhängen und sind im statischen Katalog nicht vollständig enthalten. Die Browserprüfung ersetzt keine Prüfung auf dem Zielsystem.



 
Skriptoptionen

 

  
  
Lesebefehle laufen weiterhin. Im kurzen Modus werden Änderungen auskommentiert. Für ausführbare Änderungen diese Option deaktivieren. Die Ausgabe mit Skriptgerüst unterstützt zusätzlich -WhatIf. Eigener Code muss mit der passenden Wirkung gekennzeichnet sein.

PowerHelp verwenden

 
Alle Befehle wie in der ISE
„Alle Befehle“ zeigt den eingebauten PowerShell-5.1-Katalog. Wähle ein Modul oder suche nach Name, Parameter oder deutschem Aufgabenbegriff. Im Schritt wählst du einen Parametersatz. Pflichtparameter sind sofort sichtbar; weitere Parameter werden unter „Weitere Parameter“ aktiviert. fx erlaubt komplexe Werte wie { $_.Length -gt 1MB }, @{Name="Wert"} oder $Datei.FullName. Texte werden zitiert; Listen mit Komma getrennt. Eingabevariablen erzeugen eine Pipeline. Deren Bindung hängt vom tatsächlichen Objekttyp ab. Nicht jeder Befehl liefert Daten; der Ausgabename kann hier leer bleiben. Die Wirkung ist zunächst konservativ auf Änderung / unbekannt eingestellt.
Passende Folgeschritte
Unter dem Projektnamen werden passende Schritte für den letzten Schritt der gewählten Einfügeebene vorgeschlagen. Die Hilfe ist regelbasiert und läuft offline. Parametersätze verhindern unzulässige Kombinationen; unbekannte Ausdrücke und Daten können nicht vollständig geprüft werden.
Vom Ziel zum Ablauf
Suche nach einer Aufgabe, einem Befehl oder einem Stichwort. Die Suche berücksichtigt deutsche Begriffe, Synonyme und Tippfehler. Unter „Fertige Abläufe“ findest du kombinierte Schritte. Ein Ablauf kann angehängt oder als neues Projekt geladen werden.

 
Bausteine und Variablen
Jeder Leseschritt kann seine Ausgabe in einer Variable ablegen. Nachfolgende Schritte verwenden diesen Namen. Die Ablaufprüfung erkennt fehlende Quellvariablen. Mit fx schaltest du ein Textfeld auf einen PowerShell-Ausdruck um, etwa $Datei.FullName. Normale Texte werden automatisch richtig zitiert.

 
Schleifen, Bedingungen und Funktionen
Füge einen Block hinzu und klicke auf „In diesen Block einfügen“. Weitere Bausteine landen dann innerhalb des Blocks. Mit „Im Hauptablauf einfügen“ wechselst du zurück. Schritte lassen sich per ↑/↓ oder durch Ziehen innerhalb derselben Ebene ordnen.

 
Speichern und weiterarbeiten
Das Projekt wird nach Änderungen im Browser gespeichert, soweit der Browser lokale Speicherung erlaubt. „Projekt speichern“ exportiert eine JSON-Datei inklusive Ablauf und Optionen. Die .ps1-Datei enthält ausführbaren PowerShell-Code mit UTF-8-BOM. Das Projekt ist keine .ps1-Datei; eigener Code kann über den freien Codebaustein ergänzt werden.

 
Offline und Umgebung
Alle Inhalte, Vorlagen und Prüfregeln sind in dieser HTML-Datei enthalten. Es gibt keine Online-KI und keine Netzwerkaufrufe. Das Ziel ist Windows PowerShell 5.1 auf Windows 10/11 beziehungsweise Windows Server ab 2016. Rollenmodule wie ActiveDirectory müssen bereits vorhanden sein. Auf Domänencontrollern stehen lokale Benutzerbefehle nicht zur Verfügung. Rechte und Serverrollen hängen von deiner Umgebung ab.

 
Vorschau und Fehler
Änderungsbausteine werden mit $PSCmdlet.ShouldProcess geschützt. Der Vorschau-Modus aktiviert $WhatIfPreference. Eigener Code mit „Nur lesen“ bekommt keinen solchen Schutz. Befehle zum Lesen werden dabei ausgeführt. Diese Seite ist kein PowerShell-Parser: eigene Ausdrücke, Dateiinhalt, Berechtigungen und tatsächlich vorhandene Module lassen sich offline im Browser nicht abschließend prüfen.
